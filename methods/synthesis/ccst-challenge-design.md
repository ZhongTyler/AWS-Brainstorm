# CCST 挑战编排与变形

## Contract

- Method ID: `ccst-challenge-design`
- Category: `synthesis`
- Status: `ready`
- Content version: `2`

公共约束见[方法操作约定](../OPERATING_GUIDE.md)。

## Purpose

用有限元素生成具有关系变化的挑战，再组织成可理解的序列。

## Input contract

一个核心技巧、玩家能力与约束、一处基础挑战，以及可用的内容预算。

## Use when

需要生成关卡挑战及其变化，或内容只剩数量堆叠。

## Avoid when

没有挑战序列问题的任务；不把所有作品改造成线性教学关卡。

## Procedure

1. 写出一个有进入和退出边界的基础挑战，说明玩家观察和执行的技巧。
2. 产生一项质变：加入不同的关系、行为方式或条件；再产生一项量变：调整距离、数量或时间。分别解释玩家判断如何改变。
3. 回到较简单状态，从另一个方向生成变化；按目标需要把两条变化组合，也可安排缓冲、奖励或平稳结束。
4. 检查变化是否可读、可行动及可恢复。地图尺寸、时长、难度和元素上限使用项目依据；未知仅是设计假设。
5. 选择足够支持下一判断的短序列，移交下游白盒与实际操作验证；不为填满固定阶段继续铺关。

## Output contract

基础挑战、技巧主题、各变化的关系/数量差异、序列与恢复设计、待验证条件。

## Exit conditions

已能比较不同变化并选择推进方向，或新增项开始重复、违反约束时停止。

## Single-user + AI adaptation

Agent 按用户目标设计挑战，不虚构真人试玩。CCST 是分析作者对马里奥关卡的归纳；本文短序列与纸面检查为本仓适配，不等同任天堂规程。

## Traceability

保留实际输入、父项、变化及决定的引用；图和片段是候选，不自动扩大采用范围。

## Behavior cases

### Positive case

`CASE-CCST-P01`：同一跳跃能力，先跨移动平台；质变为平台旁增加周期遮挡，量变为改变间距；第二分支改为追随移动路径，再比较组合是否要求新的判断。

### Negative case

`CASE-CCST-N01`：只连续增加敌人生命和数量，就称为五种新挑战；或把范例中约三种障碍、两三秒停留当作所有品类硬上限。
